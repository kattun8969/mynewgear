## 実装ファイル
- `wp-child-theme/category.php`: 子テーマ用カテゴリテンプレート。タイトル・説明・カテゴリナビ・アイキャッチ付きカード・抜粋・日付・ページ送り。
- `wp-child-theme/archive.php`: タグ・日付・著者等の一般アーカイブに同じカード表示（カテゴリはcategory.php優先）。
- `wp-child-theme/search.php`: 検索結果も同じカード表示に統一。
- `wp-child-theme/assets/css/mng-archive-footer.css`: ネイビー＋オレンジのカテゴリ一覧とフッターCSS。
- `wp-child-theme/functions-enqueue-example.php`: 子テーマfunctions.phpに追記するCSS読み込みスニペット（PHPファイル丸ごと置換禁止）。

## 手順
1. WPで現行子テーマとテーマファイル・既存追加CSS・カスタマイザーの現在値を確認。バックアップとファイルの復元可能性を確保する。
2. テスト環境・ステージングがあればそちらで子テーマにカテゴリテンプレートとCSSを置く。なければ既存プラグインや子テーマ編集手段を確認し、**構文エラーが出ても戻せる方法**を選択する。
3. テスト：`/category/gear`, `/category/gear/effector`, 他の子カテゴリ、タグ、検索結果、2ページ目以降、記事無しのカテゴリ、スマホ320/375px、PC1280px、ページネーション・サイドバー。
4. フッターは公開サイトで実際の要素名をブラウザ検証し、CSSセレクタが適用されることを確認する。旧ヘッダーまで背景色が波及しないか検証。
5. 記事一覧のアイキャッチが欠落している記事がある場合、プレースホルダー表示にし、無断転載画像を作らない。
6. デザイン確認後はサイト全体のヘッダーナビとの整合性・アクセシビリティ・検索からの記事導線を点検する。
7. 異常なら前のカテゴリテンプレートへ復帰し、原因をGitHub Issueに記録。SEOメタや構造化データ・既存URLは変更しない。
