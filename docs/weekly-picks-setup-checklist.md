# WordPress担当向け：6商品の初期登録シート（安全な未検証値）

GitHub PR #12・2026-11-25最終実装仕様 v0.4.2。実データは`weekly-picks-initial-candidates.csv`。

## 安全上の設計
- CSVの編集部スコアは**仮説**として登録して良い。
- **確認していない個別在庫URL、現在在庫、Pochipp ID、WordPress投稿ID、ランキング確認日・順位は空白**のまま。値が空欄なら商品はTOPに表示されない。
- `ready=0`／`verified=0`から開始。②Workが成果リンク、写真、公開済み深掘り記事、異なる2販売店の現物在庫を実地で確認した商品だけ1へ。
- 古いBD-2のような正確な発売日が不明な長期定番は、架空の日付を登録しない。公式などの旧製品確認が取れたときのみ`legacy_released=1`＋`release_source`を記録する。
- 「売れ筋TOP3」のランキングURLは現行の掲載時に改めて順位と確認日を記録（14日以内）。
- `stock_checked`は毎週更新。7日を越えるとTOP選考から自動除外される。
- WordPress管理画面では6商品未満を管理者に警告表示する。**外部販売店の在庫巡回は自動化していない**。

## 作業順序
1. Pochipp既存のBOSS BD-2商品カードにあるリンクが実際の対象商品へ飛ぶか確認。TOP上には4ショップボタンがすでにあるが、ASPで成果計上確認は未完。
2. 正確な型番のカードを6商品分整備し、サウンドハウス・もしもへリンクしている場合は最終URLを確認。**検索結果ページと個別商品ページを区別して報告**。
3. 既存の記事で各商品を深掘りしたか確認。YOASOBI記事内に名前があるだけでは「単体深掘り記事あり」と同一視しない。必要に応じ①ライターから記事を提出し、公開を優先。
4. WordPressでプラグインを有効化、画像と候補を登録して、非公開ページへ`[mng_weekly_gear count="3"]`を表示。
5. **売れ筋3＋編集部3をそれぞれ横スライド**。6件整い、ユーザー環境で表示できれば旧TOPから切替。旧TOPの商品カードはバックアップ。
6. 反映後は週ごとの在庫・ランキング・ASP成果を点検。管理画面に警告が出たら候補の補充または在庫の再調査。
